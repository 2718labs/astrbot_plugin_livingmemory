# LivingMemory S0-S6 执行路线图

本目录是后续改造的执行主稿。

- 本文件维护调查结论、问题分级、阶段顺序和整体状态。
- `S0.md` 至 `S6.md` 分别维护当前改造阶段内任务。
- `Stest.md` 维护最终系统验收；它汇总各阶段已经固定的证据，不负责临时追加实现。
- `Sfuture.md` 只记录尚未立项的远期愿景，不属于当前执行依赖链。
- 完整代码调查见 [T0-audit.md](T0-audit.md)。
- Excel 只作为 2026-08-20 的旧校对快照，不再同步。

## 已确认的主问题

当前不是单个检索参数不理想，而是整条链路逐级放大噪声：

```text
聊天窗口
  → 把“达到总结轮数”误当成“必须写一条长期记忆”
  → 低重要度只影响后续衰减，低质量或兜底结果仍可先进入 active
  → 生成混合的第一人称日记；一条记录容纳多件事
  → topic 接近一次性标题，fact 缺少自身关系
  → Atom 复制整组 topic / participant，图谱再做全组合建边
  → 生产搜索仍以整个十轮总结文档为单位，4 个名额中最多 2 个被 recent 固定占用
  → 只要文档里有一点沾边，就把长篇 persona_summary、topic、全部 facts 等整块注入
  → 模型被旧事牵引，表现为爱谈记忆、答非所问和预算浪费
```

因此，实施顺序按污染产生的先后排列：先阻止新链路继续写坏，再重建记忆产物和处理链，随后重建图谱与 Atom，最后才改召回和表达。实例旧数据只用于证明问题，不属于迁移或兼容目标。

| Current graph route | 当前实例覆盖配置为图权重 0、跨路加分 0、动态调权关闭；仍可能执行图查询 | 这是实例现状，不是上游默认；图谱缺陷真实存在，但不是当前回答污染的第一原因 |

另有实际运行观察：四条十轮总结文档合计超过 3000 token 并不少见。该数字不是上表固定样本的同一测量口径，但足以说明 `top_k=4` 不能充当注入预算。

上游基线原本默认 `graph_route_weight=0.35`、`cross_route_bonus=0.08`、`dynamic_route_weighting=true`。enhancement fork 已将动态调权默认值改为 `false`，显式开启者不受影响；图路线本身仍按 S3/S5 门槛决定是否启用。动态调权的重新设计与默认开启资格移入 `Sfuture`。

## 已确定的目标形态

十轮滑窗只是事实的来源边界，不再是召回和注入的最小单位：

```text
来源窗口 / parent memory
  ├─ fact A（自身 topic、participant、time、importance、source）
  ├─ fact B（自身 topic、participant、time、importance、source）
  └─ fact C（自身 topic、participant、time、importance、source）

查询 → fact 候选 → 相关性拒绝与去重 → token 预算装配 → 最小事实注入
```

- 保留 LM 风格的 `summary / topics / key_facts / sentiment / importance` 外壳，但 `key_facts` 升级为对象列表并标记新 schema 版本。
- `summary` 不再是长篇第一人称真源；它只是一句中性、可由 facts 派生的概览。
- 每条 fact 可选保存当前人格对该事实的简短 `persona_reaction`（情绪/想法）；它不参与事实搜索、建图、重要度或矛盾判断。
- parent memory 负责来源窗口和必要背景；生产搜索返回 fact，不能因命中一条 fact 就恢复整篇父总结。
- `top_k` 只限制候选数量，不能限制可变长度文本；最终注入必须另有整轮 token 硬预算。

## 主线

```text
T0A 源头→存储调查（完成）
  +
T0B Atom→召回→注入调查（完成）
  ↓
S0 建立新记忆准入门，并固定真实链路基线
  ↓
S1 重写“什么是一条记忆”的产物契约
  ↓
S2 统一所有新记忆的处理链并建立 canonical fact 存储/索引
  ↓
S3 按事实证据重建 topic 与图谱
  ↓
S4 收敛 Atom：接入事实主线或停用独立机制
  ↓
S5 切换到 fact 级召回，重做门槛、recent、预算和最小注入
  ↓
S6 主线稳定后再校准生命周期信号和必要体验
  ↓
Stest 汇总阶段证据，跑完整链路、时间压缩与盲测体验，给出是否通过结论

Sfuture（独立愿景，不进入当前执行链）
  ├─ 非破坏性聚合
  └─ 矛盾检测与消解
```

## 实施原则

1. T0A/T0B 已结束；从 S0 起才允许修改生产逻辑。
2. FIX 先于 FEAT；严重结构优化先于纯体验优化。
3. 先修上游数据单元，再修下游搜索；不能用更多过滤器掩盖坏数据。
4. 每一阶段只消费上一阶段已经稳定的持久字段，不同时维护两套长期语义。
5. 实例数据库只用于调查和提炼反例，不迁移、不清洗，也不承担向后兼容责任。
6. 改造和验证只在 fork 副本及干净 fixture 数据库进行，不修改线上实例配置和数据。
7. 当前图路线继续保持零权；S3 先证明图数据本身有独有有效命中，S5 再修复融合并用相同样本验证最终净收益，二者都通过后才允许启用。
8. 不把当前实例原文直接提交为测试数据；使用脱敏、缩小但保持问题结构的 fixture。
9. 每项任务必须保留一个改造前失败、改造后通过的固定样本。
10. 阶段完成后才更新下一阶段的具体任务；若字段或消费者发生变化，先修文档契约。
11. 跨记忆聚合和矛盾消解只记录在 `Sfuture`；不得为它们在 S0-S6 预埋空状态、空表或无消费者流程。
12. 十轮滑窗是来源边界，不是召回粒度；parent memory 不得重新成为整块注入载荷。
13. 只持久化一套权威 fact 对象；字符串 facts、document content 和索引文本只能是可重建投影，不能形成第二真源。
14. `persona_reaction` 可为空且必须短；只跟随命中的 fact 作为可选载荷，不进入事实索引、图关系和生命周期判断。
15. 图路线必须允许在证据不足时不贡献分数；不得再用“各自除以本路线最高分”把弱路线第一名包装成满信号。
16. 不等全部改完才开始验收：每阶段在实现前固定失败样本、实现后通过局部门槛；Stest 只做跨阶段总验和体验盲测，不在看到结果后临时改标准。
17. `dynamic_route_weighting` 默认关闭；显式配置仍可开启。其未来资格由 `Sfuture` 重新立项，不作为 S3/S5 必须完成的优化。
