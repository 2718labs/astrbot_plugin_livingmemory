# S0：建立新记忆准入门

目标：只允许有长期价值、结构合格的新记忆进入后续处理，同时把已经跑通的实例调查固化成真实链路基线。

S0 是 fork 上的第一轮改动，只负责“什么新内容允许进入”“什么情况属于正常无写入”“什么情况必须重试”，以及“以后按真实链路验收”。

非目标：不处理实例旧记忆，不修改线上配置，不暂停衰减/清理，不处理默认关闭的 consolidation，不重写完整记忆结构，也不调整召回排序。

## S0-01：真实生产基线

- 复放顺序必须与生产一致：消息触发 → 搜索 → 过滤 → recent 合并 → `top_k=4` → 最终格式化。
- 正向样本检查最终四条里是否包含目标，不再用 `k=8` 候选池推导生产 `hit@4`。
- 负向样本至少包含寒暄、笑声、道别、新问题和无关技术报错。
- 记录最终文档 ID、强制 recent 来源、注入字符/token、延迟和空结果。
- fixture 使用脱敏内容，不提交当前实例原文。

## S0-02：写入价值判断

- 总结触发轮数达到阈值，不等于必须生成长期记忆。
- 当前 prompt 已让模型用 `importance=0.0–0.2` 表示无意义内容，但现有代码仍会先写 active，再等待衰减和清理；这是保留信号，不是写入准入。
- S0 复用现有 importance，不另建复杂评分器；但模型给出的 importance 或 `store` 意见都只能是证据，不能绕过内容契约。
- 只有内容在当前窗口结束后仍可能被复用，才允许进入长期存储；稳定身份、偏好、关系、计划、反复出现的问题和明确要求记住的内容属于候选。
- 纯寒暄、一次性斗嘴、临时报错过程、即时吃饭催促等默认不写，除非其中包含独立、可复用的信息。
- `agent_memorize_tool` 的明确保存意图可以绕过“是否值得”的判断，但不能绕过结构和质量校验。
- 不在 S0 设计复杂打分器；先固定清楚的正例、反例和“不确定则不自动写”的行为。

三种结果的语义固定为：

- `store`：模型提出可保存内容，且写前内容检查通过；才允许创建 active 文档和下游对象。
- `skip`：本窗口被成功判断为没有长期价值；不写任何记忆，但正常推进总结滑窗，避免反复处理同一批无价值消息。
- `invalid`：格式、字段或内容产物不合格，系统无法作出可靠判断；不写记忆、不伪装成 `skip`，保留来源窗口并进入既有重试路径。

## S0-03：低质量结果拒写

- 写入前检查固定 JSON 外壳、必需字段、字段类型、非空事实和明显泛化/兜底内容；完整对象化 fact 契约留到 S1。
- 首次结构不合格时最多允许一次“只修格式、不新增、删除或改写事实”的修复；修复结果必须重新走同一校验。
- 修复后仍失败、正则只提取到零散字段、或只剩默认“对话记录”等兜底文本时，统一返回 `invalid`，不创建 active 文档及其下游对象。
- 失败结果只保留最小处理记录和来源窗口供重试，不为坏产物额外建立“不可召回记忆”状态。
- `summary_quality=low` 不再只是一个写入后的标签；对新链路而言，它必须在落库前终止本次写入。
- 本任务只阻止明显坏产物；完整的新产物契约在 S1 实现。

## S0-04：准入回归集

- 写入正例：稳定偏好、身份事实、长期计划、明确“请记住”。
- 写入反例：寒暄、一次性玩笑、临时报错排查、重复无新增内容。
- 混合窗口：只有其中独立且可复用的内容允许进入候选。
- 分开验证 `skip` 与 `invalid`：前者推进滑窗且零写入，后者保留待重试窗口且零写入。
- 验证模型错误高估 importance 或声称 `store` 时，明显无长期价值的内容仍不能通过写前检查。
- 这些样本只验证新链路产物，不要求旧实例数据通过。

## 完成条件

- [ ] 生产顺序基线可以重复运行，并显示最终注入而不只显示候选池。
- [ ] 反例窗口不会新增 active 文档、Atom 或图 entry。
- [ ] 低质量/兜底结果不会进入 active 搜索索引。
- [ ] `skip` 与 `invalid` 的滑窗和重试行为可分别验证，不会互相冒充。
- [ ] importance 继续服务后续保留/衰减，但不再被当作唯一准入条件。
- [ ] fork 的干净 fixture 数据库只包含通过准入的新记忆。
- [ ] S0 不触碰实例旧数据、维护任务、搜索和注入行为。
