# S0：建立逐事实准入门

目标：先把同一件事收束成窗口结束时成立的最终状态，再区分本窗口新证据与 Bot 复述的旧内容，最后逐条判断候选 fact 是否值得长期保存；只有通过这三层判断且输出格式合格的事实才能进入现有存储和下游处理。同时把已经跑通的实例调查固化成真实链路基线。

S0 是 fork 上的第一轮改动，只负责“窗口最后到底成立什么”“哪些内容是本窗口新确认的”“每条新事实能不能写”“原始回答能不能处理”“整窗应当推进还是重试”，以及“以后按真实链路验收”。十轮滑窗只是来源范围，不能成为一个只能整体保存或整体跳过的记忆单元。

非目标：不处理实例旧记忆，不修改线上配置，不暂停衰减/清理，不处理默认关闭的 consolidation，不完成 S1 的全部 fact 字段和持久化结构，也不调整召回排序。

## S0-01：真实生产基线

- 复放顺序必须与生产一致：消息触发 → 搜索 → 过滤 → recent 合并 → `top_k=4` → 最终格式化。
- 正向样本检查最终四条里是否包含目标，不再用 `k=8` 候选池推导生产 `hit@4`。
- 负向样本至少包含寒暄、笑声、道别、新问题和无关技术报错。
- 记录最终文档 ID、强制 recent 来源、注入字符/token、延迟和空结果。
- fixture 使用脱敏内容，不提交当前实例原文。
- 本任务只固定改造前的尺子，不在 S0 修改召回、recent 或注入行为。

## S0-02：原始回答格式门

原始回答必须先经过独立格式门，只有通过后才允许进入事实准入和记忆构建：

```text
LLM 原始回答
  → 去掉完整包裹回答的 Markdown 代码围栏
  → JSON 解码
  → 检查顶层字段、字段类型和每条 fact 的最小结构
  → 通过后才进入业务处理
```

- 自动总结的 `key_facts` 改为候选 fact 对象列表；S0 至少要求 `fact`、`action` 和 `importance`，其中 `action` 只能是 `store` 或 `skip`。
- 缺少必填字段、字段类型错误、未知 action、空 fact、importance 越界或顶层不是 JSON object 时，均视为格式不合格；不得静默补默认必填值。
- 首次格式不合格时最多允许一次“只整理为目标 JSON、不得新增、删除或改写事实”的修复；修复结果重新经过完全相同的格式门。
- 修复后仍失败时返回窗口级 `invalid`；不得再用正则捞字段，不得生成“对话记录”等兜底记忆。
- 这里的“先校验再解析”是指先完成 JSON 解码和纯结构校验，再把结果交给记忆业务；不会在无法读取 JSON 时假装已经得到可靠事实。

S0 的最小处理形态：

```json
{
  "summary": "只概括准备保存的事实",
  "topics": ["驾考"],
  "key_facts": [
    {
      "fact": "张三周三要参加科目二考试",
      "action": "store",
      "importance": 0.8
    },
    {
      "fact": "张三刚才说有点饿",
      "action": "skip",
      "importance": 0.1,
      "reason": "即时状态，没有长期复用价值"
    }
  ],
  "sentiment": "neutral",
  "importance": 0.8
}
```

这只是 S0 的处理契约：`action` 和被跳过的候选不持久化。fact 自身的 topic、participant、time、source、reaction、稳定 ID 和最终 v3 存储结构仍由 S1 完成。

## S0-03：逐事实写入价值判断

- 总结触发轮数达到阈值，不等于必须生成长期记忆，也不等于十轮内容只能整体保存或整体跳过。
- LLM 对每条候选 fact 给出 `store / skip`；顶层不再让 LLM 另写一个可能和 facts 冲突的 `memory_action`。
- 程序从通过格式门的 facts 推导窗口结果：至少一条 fact 通过准入则为 `store`；零条通过且回答格式合格则为 `skip`；原始回答或修复结果不合格才是 `invalid`。

准入顺序固定为：

```text
1. 最终状态：同一件事有前后变化时，后续明确否认、纠正、澄清或约定覆盖旧说法。
2. 新证据：只吸收本窗口中新确认的内容；Bot 复述的旧记忆和人格设定不重新写入。
3. 长期价值：把 fact 单独放到未来另一场对话中，仍能帮助理解人物、关系或未完成事项才 store。
4. 逐条决定：每条候选独立 store / skip，程序再推导整个窗口的三态结果。
```

- `store` fact 必须具体、非空，并在当前窗口结束后仍可能被复用；稳定身份或偏好、关系边界或已接受约定、待办计划、持续问题、重要事件和明确要求记住的内容属于候选。
- `skip` fact 表示纯寒暄、一次性斗嘴或玩笑、临时报错过程、即时状态、单次称呼或动作、重复无新增内容；它只用于本次处理和测试，不创建任何持久记录。
- 被后续说法推翻的中间解释不得作为另一条事实保存；来源只指向最终说法及其直接依据。
- Bot 自己复述的旧记忆、对用户过去行为的单方面声称、人格设定和自我介绍只属于处理上下文；除非用户在本窗口直接确认或补充，否则不得形成新的长期记忆。
- 同一个玩笑在单个窗口里重复多次仍是一次性玩笑，不算持续问题；出现次数、篇幅或语气强度不能代替长期价值。
- 单次使用昵称、亲昵称呼或做出某个动作不自动等于稳定偏好；需要明确表达、跨窗口一致证据或双方约定。
- “真实发生过”本身不等于值得长期保存；不能明确归入 `store` 候选类别时默认 `skip`。
- S0 复用现有 importance，不另建复杂评分器；importance 或模型给出的 `store` 都只是准入证据，不能绕过格式和内容规则。
- `agent_memorize_tool` 的明确保存意图可以绕过“是否值得”的判断，但不能绕过结构和质量校验。
- 不确定时不自动写；不为了让 `key_facts` 非空而编造候选。

窗口结果语义固定为：

- `store`：存在至少一条合格的 `store` fact；只把这些 facts 投影给现有下游，任何 `skip` fact 都不得经 summary、key_facts 或兜底正文重新进入存储。
- `skip`：原始回答格式合格，但没有任何 fact 获准保存；零写入并正常推进总结滑窗，避免反复处理同一批无价值消息。
- `invalid`：格式、字段或候选结构不合格，系统无法可靠处理；零写入、不伪装成 `skip`，保留来源窗口并进入既有重试路径。

## S0-04：接通存储、滑窗和重试

- `store` 才允许创建 active 文档和当前既有的下游对象；传给旧消费者的 `key_facts` 暂时是获准 fact 文本的单向投影，不新增第二套持久真源。
- `skip` 不调用 document、Atom、graph 或索引写入，但要把 `last_summarized_index` 推进到本窗口末尾并清除 pending summary。
- `invalid` 不调用任何写入，也不推进 `last_summarized_index`；沿用同一来源窗口和现有 pending summary 重试机制。
- 单次回答中只要有一个候选 fact 的必需结构损坏，就先整体走一次格式修复；修复仍失败时整窗 `invalid`，不在写入后遗失坏候选。
- `summary_quality=low` 不再只是一个写入后的标签；对新链路而言，它必须在落库前终止本次写入。
- S0 只把通过准入的事实投影给现有存储；完整 parent/fact 模型、稳定来源和事实级索引在 S1/S2 实现。

## S0-05：准入回归集

- 写入正例：稳定偏好、身份事实、长期计划、明确“请记住”。
- 跳过反例：寒暄、一次性玩笑、临时报错排查、即时状态、重复无新增内容。
- 混合窗口：同一次输出允许同时有 `store` 和 `skip` facts，最终只写入获准 facts。
- 全部跳过：格式合格、零写入、滑窗推进。
- 格式失败：缺字段、错误类型、未知 action、空 fact、非法 JSON；一次格式修复仍失败后零写入且窗口保留待重试。
- 验证模型错误高估 importance 时，明显兜底或结构不合格的内容仍不能通过写前检查。
- 验证任何 `skip` fact 都不会出现在 document content、metadata key_facts、Atom、graph entry 或索引文本中。
- 这些样本只验证新链路产物，不要求旧实例数据通过。

## 实现与验证记录

- 自动总结提示词和不可覆盖的输出契约都改为逐 fact 的 `fact / action / importance`；顶层 `memory_action` 明确禁用。
- 原始回答只接受完整 JSON 或完整 Markdown JSON 围栏；必填字段、类型或候选结构不合格时，只允许一次不改事实的格式修复。旧正则提取、必填默认值和“对话记录”兜底已退出自动总结链。
- `MemoryProcessingResult` 固定 `store / skip / invalid` 三态。`store` 只向现有下游投影获准事实文本；`skip` 零写入并推进窗口；`invalid` 零写入、保留窗口并记录 pending retry。
- 自动与手动总结入口均使用同一三态结果；显式记忆工具仍保留原有明确保存入口，不受“是否值得”判断影响。
- 生产基线测试使用实际 `MemoryEngine.search_memories()` 的过滤与 recent 合并，再经过真实注入格式化；固定检查 `top_k=4` 的最终 ID、recent 来源、最终注入字符/估算 token、耗时和空结果，负例覆盖寒暄、笑声、道别、新问题和临时报错。
- 回归覆盖混合窗口、全跳过、低 importance、一次修复成功、修复仍失败、缺字段、顶层冲突、泛化兜底、自动窗口推进/保留和手动 skip。
- 补充“中间说法被后续纠正”的准入契约回归：要求保留最终互动偏好与约定，排除已被否认的解释、Bot 自己复述但用户未确认的旧事、单次称呼行为和窗口内反复出现的一次性玩笑。
