# S1：重写记忆产物契约

目标：在 S0 已建立的逐 fact 准入结果上，明确“获准保存的一条记忆完整长什么样”，把旧式字符串投影升级为 LM 风格、对象化、可独立召回、可建立真实关系的 fact 数据。

S1 只改自动总结的新产物及其现有写入路径；不迁移旧库、不重建图、不切换生产召回，也不决定 Atom 是否保留。明确记忆工具、导入和 WebUI 编辑等其他入口仍由 S2 统一。

## S1-01：一条记忆只承担一个中心

- 一条持久记忆只围绕一个可复用中心；同一窗口出现多件事时允许生成零条、一条或多条记忆。
- 十轮滑窗只提供来源边界；parent memory 保存来源和必要背景，fact 才是后续独立检索、建图和注入的候选单位。
- 保留 LM 熟悉的 `summary / topics / key_facts / sentiment / importance` 外壳，但明确标记新 schema 版本；这是 LM 风格延续，不宣称与旧 `list[str]` 运行时类型兼容。
- Muse 的“事情经过 / 重要事实”在 LM 中分别对应短 summary / 对象化 key_facts，不再额外要求模型输出 Markdown 双标题。
- `summary` 降格为一句中性概览，优先由主 facts 派生；它不是独立事实真源，也不能重新承担整块召回载荷。
- 明确区分稳定资料、偏好/关系、计划、事件和临时过程；分类服务于字段和消费者，不追求繁复本体。

目标输出形态（本例中的张三是虚构用户，`[Bot: AstrBot]` 是当前 Bot）：

```json
{
  "memories": [
    {
      "key_facts": [
        {
          "fact": "张三将在2026年8月26日参加科目二考试",
          "topics": ["驾考"],
          "importance": 0.8,
          "persona_reaction": {
            "emotion": "有些担心，也有点期待",
            "thought": "希望张三能够顺利通过"
          }
        }
      ]
    }
  ]
}
```

时间复用原版 LivingMemory 的简单方案：模型按说出相对时间的消息日期，把“今天、明天、下周三”等表达直接改写为 fact 正文中的具体日期。消息发送时间由程序作为来源元数据另存；正文没有时间表达时，不从消息头补造事件时间。独立时间对象和按时间检索不属于 S1，见 `Sfuture`。
模型只输出值得保存的 facts；不值得保存的候选不必逐条列出。`summary`、memory topics、participants、sentiment、memory importance、稳定 ID 和来源边界均由程序派生。窗口级 `store / skip / invalid` 由程序根据是否存在合格 facts 和格式校验结果推导。

## S1-02：独立事实

- 每条 fact 只表达一件可判断的事，保留必要主体、时间、条件和状态。
- 自动总结只输出获准事实；每项必含 `fact / topics / importance`，有价值时可带 persona reaction。相对时间必须在 fact 正文中改写成具体日期，不单列结构化字段。
- participants 由程序按 fact 中出现的窗口发言者昵称绑定；summary、文档 topics、sentiment 和文档 importance 从 facts 派生，不让模型重复填写。
- 承诺、约定和未完成事项仍是普通 fact，不新增专用种类、状态、到期或调度字段。事实文本负责写清主体、是否被接受和必要时间。
- `fact` 必须脱离十轮摘要仍能看懂，不能依赖“她”“那个”“后来”等无法回到来源的指代。
- 不逐句摘录评价和对话过程；同一事件的原因、发展与结果应合成一条以后可以整体接续的 fact，不把无关事件硬塞在一起。
- 同一事实的不同措辞通过规范化处理，不靠在文本尾部重复一遍来增强召回。
- 允许某条记忆没有可保存 fact；此时不应为了满足 schema 编造内容。
- scope、fact ID、schema version 和窗口来源指纹由代码补充，不能交给模型编造。
- 不为看起来“完整”而照搬 confidence、expires、矛盾状态等无当前消费者字段；需要时再按阶段增加。

## S1-03：可复用 topic

- topic 表示跨记忆可复用的概念，例如“考研”“睡眠”“插件开发”，不是“今天上午的后续斗嘴”式事件标题。
- 总结时提供同 scope 已有 topic 候选；只有能够确认是同一概念时才复用，没有确定候选才新建。
- 此处解决的是名称规范、稳定 ID 和同一节点复用，不做近义聚类、跨记忆综合或 topic 合并。
- 不使用封闭词表，也不为了降低单例率把相关但不同的概念强行归为一类。
- 保存原始候选和最终选择，便于后续检查为什么复用或新建。

## S1-04：事实级关系

- 每条 fact 只绑定自身相关的 topics 和 participants。
- 文档级标签可以保留用于浏览，但不得再复制成每条 fact 的关系。
- 关系必须能回到具体 fact；“出现在同一摘要”不等于彼此有关。
- S3 只消费这里落盘的显式关系，不再自行猜测全组合。

## S1-05：去掉长篇人格总结

- 新记忆不再生成长篇 `persona_summary`；原来的第一人称自由作文不能作为搜索、建图、注入或展示的权威内容。
- `summary` 只保留中性的一句概览；展示默认使用主 fact，而不是重新展开十轮对话。
- 每条 fact 可以带一个很短、可为空的 `persona_reaction`，其中 emotion / thought 分别记录当前人格对该事实当时的反应。
- 如果参与者明确说“我很紧张”，这是 fact；“我替她紧张”才属于当前人格的 reaction，二者不得混淆。
- reaction 不得复述 fact，不得为了人格感强行编造，每项最多一小句；没有明确或有价值的反应时为空。
- reaction 不参与事实索引、topic/graph、importance、生命周期和未来矛盾判断；S5 只在对应 fact 命中且预算允许时把它作为可选载荷附上。

## S1-06：稳定来源

- 保存消息首尾 ID、消息数量、scope、生成版本和 source fingerprint。
- 同一窗口重试必须命中同一幂等键，不能创建第二条 active 记忆。
- 不再使用会随消息插入/删除而漂移的 OFFSET 作为长期来源边界。
- 自动总结、明确记忆工具和后续处理都必须保留各自的窗口或调用来源边界。
- 每个 fact 获得稳定 fact ID，并能回到 parent memory；parent 保存完整窗口来源边界，不再伪装成 fact 级语义证据。

## S1-07：契约回归集

- 覆盖单主题、多主题、无后续价值、稳定偏好、短期承诺/约定、时间变化、多人物和明确记忆请求。
- 检查生成条数、对象字段、事实独立性、自包含程度、topic 复用、事实级绑定和窗口来源回链。
- 检查 summary 能否由 facts 派生，以及 persona reaction 是否可为空、足够短、不冒充人物事实。
- 为仍在迁移中的 LM 内部消费者提供统一的 fact-text 投影方法；不得把字符串版 facts 作为第二套持久数据保存。
- 多次运行允许措辞变化，但稳定字段和关系不能无界漂移。

## S1-08：保留原版容量，只细化 fact 粒度

- 沿用原版“单条 memory 最多 5 个 facts”的上限，不把提高质量误解为无限增加 fact 数量。
- 多中心只是让不同事情不再挤进同一个 parent；一个十轮来源窗口无论拆成几个 parent，合计仍最多 5 个 facts，不能把容量放大为 25。
- 一条 fact 可以完整表达同一事件的原因、发展和最终结果；不能把一次来回中的每句动作都拆成独立长期记忆。
- 原始回答超量时只允许一次压缩修复。压缩只能合并或删除铺垫、重复说法，不得新增事实或改变人物归属、否认、纠正、约定和最终结论；仍超量则整窗不写入。

## 实现记录

- 自动总结顶层契约改为 `memories[]`；一个来源窗口可生成零条、一条或多条单中心记录，两条真实写入入口逐条持久化。
- 沿用原版十轮总结最多 5 个 facts 的容量：单个 memory 仍最多 5 条，多中心外壳下整个窗口合计也最多 5 条，不能因拆成多个 parent 把上限放大到 25。模型超量时只允许一次基于原回答的压缩修复，不得补造事实，修复仍超量则整窗不写入。
- 新记录标记 `memory_schema_version=v3`；`key_facts` 是唯一持久事实形态。默认 LLM 输出不再包含 `action / reason / source / source_indexes / participants / summary / sentiment`，旧自定义提示词多给出的字段会被丢弃。
- 每条 fact 由代码补 `fact_id / parent_id` 和可确定的 participant 绑定，并保存自身的 topic、importance 和可选 reaction；不再生成 fact 级 `source_message_ids`。
- topic 只做 Unicode/空白规范化和同 scope 精确候选复用；保存稳定 topic ID、原始名称、最终名称及 `created / reused` 决定，不做近义聚类。
- 来源边界保存首尾消息 ID、完整消息 ID 列表、数量、scope、生成版本和内容指纹；数据库写入按来源单元幂等键复用已有 active 记录。
- 相对时间沿用原版方式直接改写进 fact 正文；完整来源时间由程序另外保存。当前不持久化 `fact.time`，也不建设按时间过滤或排序。
- 统一 fact-text 投影只在旧消费者读取时临时生成；现有 Atom 过渡读取按每条 fact 自身实体分类，旧图读取不会把对象序列化成字典文本。图关系是否采用这些显式绑定仍属于 S3。
- WebUI 详情可读展示 v3 fact；为避免旧文本编辑器破坏对象契约，v3 记录的旧式编辑/重新总结入口暂不展示，待 S2 统一写入入口后恢复。
- 回归覆盖多中心拆分、空输出、精简对象字段、相对时间正文改写提示、稳定 ID、topic 复用、fact 级实体、幂等写入和真实 SQLite/FAISS 消息链路。
