## T9：LLM 为 canonical fact 生成短标题

### 问题

当前图谱在展示层删除时间、人物和叙述前缀后，再把 fact 正文截成 6–8 字。它能缩短文字，但无法保证标签有区分度：`提到交付延期…`、`询问可否改期…`、`解释初次合作…`仍以报告动词开头，多个节点扫视时接近“提到… / 询问… / 解释…”，没有真正标出事实主题。

这不是继续调截断长度能够解决的问题。标签所需的语义信息应在写入记忆时由 LLM 与 canonical fact 一起生成，而不是由前端从完整句子里猜。

### 目标数据契约

- 每条新 canonical fact 增加独立的 `short_title`，由同一次 LLM 提取调用生成，不增加图谱展示时的 LLM 请求。
- `short_title` 默认 4–6 个中文字符，使用能直接区分事实的名词或短语；极简概念在不丢失区分度时可以更短。
- 删除日期、人物复述前缀、标点和尾部省略号；避免以“提到、询问、解释、表示、回应”等报告动词充当核心标签。
- 同一条记忆内的多个标题必须彼此可区分，不能只满足单条格式正确。
- 示例目标：`交付延期`、`会议改期`、`初次合作`。

### 写入与读取链路

- 扩展 LLM 输出 schema、解析、格式修复和校验，使 `fact` 与 `short_title` 成对进入 canonical fact 数据。
- 持久化 `short_title`，并在在线写入、重建、导入导出、Page API 和图谱快照中保留该字段。
- fact 图节点优先显示 `short_title`；hover 和记忆详情继续展示完整 `fact` 正文，不新增可见 UI 元素。
- 存量 fact 缺少 `short_title` 时必须有兼容回退，不能因为新字段缺失而丢节点；是否批量调用 LLM 回填存量数据另行决定。

### 验收标准

- 固定多事实样本，验证 LLM 输出、schema 校验、落库、读取、图谱快照和前端标签整条链路。
- 对同一记忆中的相近事实，短标题在脱离全文时仍可互相区分。
- 图上不再把展示层的机械截断作为新写入 fact 的主要命名方式；完整正文仍可在 hover / 详情中查看。
- 不增加图谱节点、浮层或常驻说明元素。
- 20 个节点、32 条边这类小图仍然混乱时，应继续修布局；短标题只改善辨识度，不能用整齐的拓扑掩盖数据中不存在的结构。

### 非目标

- 不让前端或每次打开图谱时额外调用 LLM。
- 不用短标题替换 canonical fact 正文、来源证据或检索文本。
- 不把径向排列、聚类等布局约束当成数据关系本身。

## T10：全量图谱 Louvain 社区与凸包

### 启动条件

- 仅面向显式打开的数百节点全量图；当前默认概览及不超过 80 节点的子图继续使用真实连通分量布局。
- 只有原始节点规模已经无法直接清晰展示时才启用，不为当前小图提前增加聚类复杂度。

### 目标

- 基于真实图边运行 Louvain 社区检测，社区结果必须稳定、可复现，并防止人物枢纽把全图吞成少数巨型社区。
- 全量首屏以社区聚合结果展示；社区大小编码成员数量，社区间连线编码真实跨社区关系。
- 下钻到社区内部后再展示原始节点，并可返回全量总览。
- 使用社区成员坐标的凸包绘制半透明边界；凸包只能表达检测到的真实社区，不用纯装饰分区冒充数据结构。

### 验收标准

- 数百节点全量图首屏不直接铺开全部原始节点，且能从聚合总览进入任一社区。
- 同一份数据重复加载得到一致的社区划分与整体位置。
- 凸包与社区成员一一对应，不遮挡主要标签和交互命中区域。
- 默认概览的小型连通图不受本项影响。

## T11：webui 编辑功能与显示口径兼容

### 问题

2026-08-25 起，父记忆条目的显示值改为子 fact importance 的自加权（Σ(imp²)/Σ(imp)），存储值保持 max 语义不变。webui 编辑面板的"重要性"滑条编辑的是父级存储值（`documents.metadata.importance`，供检索排序、图谱节点使用），与列表/详情的加权显示口径不同：用户手动改父值后，列表显示值（加权）可能不变，产生"改了没反应"的困惑。

### 现状

- 显示：列表与详情父值 = 子 fact 自加权（仅显示层，存储与排序不动）。
- 编辑：滑条修改父级存储值；子 fact 各自 importance 与 persona_reaction 不受影响。
- 编辑面板已加一行小字注明口径差异。

### 目标

- 明确"编辑父值 = 调整检索/排序/图谱权重，不影响列表综合显示"的语义，编辑面板有对应说明。
- 评估是否提供"按 parent 批量编辑子 fact importance"的入口；当前不做，只记录评估结论。
- 编辑保存后，显示与存储的口径差异不产生误导（含编辑后刷新、批量编辑两条路径）。

### 验收标准

- 编辑父 importance 保存后，列表加权显示值不变属预期行为，UI 有说明且不报错。
- 单条/批量编辑不破坏 fact 级 importance 与 persona_reaction。
- 编辑面板的提示文案在 zh/en/ru 三语言下均存在。
