# S3：按事实证据重建 topic 与图谱

目标：消除同文档全组合建边，只保存能回到具体事实和来源的关系；图路线没有稳定净收益时继续保持关闭。

## S3-01：显式关系建边

- 图谱只消费 S1 已落盘的 fact-topic / fact-person 关系。
- 不再因为 topic、person 和 fact 出现在同一文档，就生成所有可能的组合边。
- 一条边必须能指向具体 fact ID、parent ID 和直接来源记忆。
- `summary`、parent context 和 `persona_reaction` 都不是事实关系证据，不参与节点或边生成。
- 不用一次向量相似度直接创建永久关系。

## S3-02：topic 身份与节点复用

- 规范 topic 名称、scope 和稳定 ID，写入时优先复用已有概念。
- 只有规范化后可确认是同一概念的输入才共用节点；近义、相关和共同出现都不足以自动合并。
- 近义聚类、alias 推断、跨记忆 topic 合并和上层主题综合全部移入 `Sfuture`。
- 目标是让多个事实汇聚到同一概念，不是把所有记忆压成少数大类。

## S3-03：共享边的来源证据

- edge 与 memory evidence 分离；同一语义边可由多条记忆共同支持。
- 删除或归档一条记忆只删除自己的 evidence。
- 仍有其他来源时保留边；最后一个来源消失后才回收边和无引用节点。
- I01 在这里与新 schema 一次修完，不再先做临时双实现。

## S3-04：统一 rebuild

- 在线写入和 rebuild 调用同一个图构建器，输入都是 S2 的 canonical 数据。
- legacy 文档没有显式事实关系时不自动补造图边。
- 同一 active 集合经过在线写入和全量重建后，应得到相同的规范化图签名。

## S3-05：真正关闭图路线

- `graph_memory.enabled=false` 或有效图权重为 0 时，不初始化/调用生产图搜索。
- 融合结果中不允许零贡献图候选占位。
- 该修复属于图阶段的边界收口，不再作为 S0 的第一任务。

## S3-06：固定双路满信号 bug

- 构造一组受控样本：document/fact 路线有强且正确的候选，graph 路线只有弱或无关候选。
- 记录两条路线归一化前的原始信号、归一化后的信号和最终名次，明确复现“各自除以本路线最高分后，两边第一名都变成 1”的现状。
- 固定验收语义：一条路线没有可靠候选时必须能够不贡献，不能因为非空就拿到完整路线权重。
- S3 只锁定失败样本和正确行为，不在这里凭感觉指定最终融合公式；具体修复和最终注入验收放在 S5。

## S3-07：修复图谱概览与全量按钮

- 已确认当前前端进入图谱页时会调用 `ensureGraphScene → fetchOverview`，而 `fetchOverview` 固定发送 `full_graph=true`；“全量图谱”按钮仍调用同一个 `fetchOverview`。因此，页面首次进入已经加载全量图，未设置筛选时再点按钮只是重复同一请求。
- 页面首次进入改为请求带节点/边上限的受限概览；不能再默认绕过后端已有的 overview 限制。
- “全量图谱”按钮保留，但必须显式切换到全量模式；从局部检索、记忆定位或受限概览点击后，画布与可见节点/边计数必须发生对应变化。
- 前端测试不再断言所有 overview 请求都带 `full_graph=true`；分别固定“首次进入受限”和“点击按钮全量”两个行为。Page API 继续保留显式全量能力。
- 历史证据：旧调查文档 `memory-system-analysis.md` 第 4.1 节已记录默认全量请求、无节点/边上限以及旧测试把该行为固化的问题；本路线图已把结论和验收完整写入，不依赖旧文档决定实现。

## S3-08：图数据价值验收

- 比较 document-only、document + graph 和 graph-only。
- 逐例显示“查询 → topic/person → fact → source memory”，人工判断联想是否真实。
- 样本不能继续只来自单人格、单会话双人私聊；至少覆盖多会话、常见群聊、多人物关系、直接事实、间接联想和时间问题，并按场景分别报告。
- target 与相关性等级应在查看各路线结果前固定；能由不同的人盲标时优先盲标，避免出题、实现和判卷使用同一套偏好。
- 同时报告 Hit@1、Hit@3/最终 k、MRR、图独有有效命中、错误边率、每条记忆产生的 evidence 数和额外延迟；不能再用单一 Hit@1 判图是否有帮助。
- S3 判断重建后的图是否产出可靠的独有候选；融合后的最终净收益由 S5 在修复 I18 后判断。
- 如果图数据没有稳定的独有有效命中，生产继续保持 document-only；这也是合格结论。
- 历史证据：旧调查文档 `foundation-audit.md` 第 3、5 节已指出旧样本只覆盖双人私聊、直接题偏多，并建议使用多会话、群聊、盲标和前几名帮助度；这些限制现已成为本阶段的正式验收条件。

## 完成条件

### 实现记录（2026-08-21）

- `GraphExtractor.extract()` 按 `memory_schema_version == "v3"` 分流到新的 `_extract_from_canonical()`：每个 fact 只连自己的 `topic_refs` / `participant_refs`，边携带 `evidence`（source_memory_id、fact_id、parent_id）。`summary`、persona_reaction 不参与建边。
- topic / person 节点使用 S2 稳定 ID（`topic_id` / `participant_id`）作为 canonical value，跨记忆同概念自然复用；仅字符级规范化，不做近义合并。
- `_extract_legacy()` 删除 topic×fact、person×fact、person×person 三组全组合边；legacy 文档只贡献节点与可检索 entries，不再补造图边（I09）。
