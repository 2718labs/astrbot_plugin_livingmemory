# S4：收敛 Atom 的角色

目标：结束 Atom “独立存储、独立分类、独立生命周期，但没有生产召回消费者”的悬空状态。

当前默认判断：S1/S2 已经建立 canonical facts 和事实级索引。除非对照实验能证明 Atom 作为这套事实层的物理实现有明确净收益，否则停用独立 Atom Retriever、FTS、分类和生命周期，不再维护第二套事实语义。

## S4-01：只允许一个事实真源

必须回答：S1/S2 的 canonical facts 是否已经承担了 Atom 想承担的全部职责，以及 Atom 是否还能提供无法由同一 fact store 低成本完成的生产收益？

比较以下内容：

- 事实级命中是否更准确；
- 注入是否明显更短；
- 查询和写入成本；
- scope、来源和父文档装配复杂度；
- expired / forgotten 对用户到底意味着什么；
- 是否需要再维护一套类型、状态和索引。
- 是否能保持同一个 fact ID、对象契约和返回形态，而不是让 S5 识别两套事实。

禁止继续保持两套长期事实：一套真正被文档搜索使用，另一套只在后台过期。

## S4-02：对照实验

- 使用同一批相关、无关、时间变化和多事实样本比较 canonical fact store/retriever 与 Atom 实现；document route 只作为旧基线，不再是目标事实层候选。
- Atom 命中必须进入最终生产注入后才算有效，不能只报告 Retriever 能返回。
- 比较命中、负向注入、token、延迟、错分类和错误过期。
- 两种方案必须向 S5 提供同一 fact hit：fact ID、parent ID、事实文本、必要关系、分数和可选 reaction 载荷。
- 只有稳定净收益才能选择方案 A；“代码已经存在”不是保留理由。

## S4-03A：Atom 成为唯一事实层

仅在对照实验胜出时实施：

- S1 facts 直接落为 Atom，停止并行复制第二份事实文本。
- Atom 真正参与自动召回和明确搜索工具。
- 命中后只装配必要父文档上下文。
- 类型、scope 和状态与生产召回使用同一契约；S5 在统一 fact hit 之后执行预算装配。
- persona reaction 只作为 fact payload 跟随返回，不进入 Atom 分类、FTS 或向量正文。
- expired / forgotten 必须确实改变事实可召回性，父文档不能绕过状态继续提供同一事实。

## S4-03B：停用独立 Atom

若没有明确净收益，采用此方案：

- 停止初始化独立 Retriever、FTS、分类器和定时生命周期。
- S2 canonical fact store/retriever 直接成为唯一生产事实层；图谱也直接消费 facts，不再要求 Atom 作为中转。
- 不迁移、清洗或删除实例旧 Atom；fork 新链路只停止生成和消费它们，测试只使用干净 fixture。
- 用户可见召回不得因停用而退化。

## S4-04：新链路处理

- 方案 A：S2 canonical facts 直接以 Atom 形式持久化，不再先写另一份 fact 再复制；不读取或迁移实例旧 Atom。
- 方案 B：新链路不再生成 Atom，也不启动相关后台任务。
- 无论选择哪条路，都不能让旧 Atom 与新 facts 同时作为两套 active 真源。
