# S4：收敛 Atom 的角色

目标：结束 Atom “独立存储、独立分类、独立生命周期，但没有生产召回消费者”的悬空状态。

决策结果：**方案 B——停用独立 Atom，canonical fact store 承担唯一生产事实层**。S1/S2 的 canonical facts 已覆盖 Atom 想承担的全部职责，对照实验没有发现任何需要保留 Atom 的净收益；相反，Atom 自身存在可复现的分类、时间基准和中文检索缺陷。

## 已确认基线

| 项目 | 当前实例 |
|---|---:|

| `unknown` | 119（约 39%） |
| `factual` | 89 |

已发现把吃饭经过分成 `planned` 等明显错例；Atom 通常还复制父文档全部 topics。更关键的是，`MemoryEngine.search_memories()` 不消费 AtomRetriever，Atom 状态变化不会阻止父文档被召回。

## S4-01：只允许一个事实真源

### 对比结论（方案 B 的依据）

| 维度 | canonical fact（S1/S2） | Atom（旧机制） |
|---|---|---|
| 真源 | `memory_facts` 表：稳定 fact_id / parent_id / scope / persona / importance / status | `memory_atoms` 表：第二份事实文本副本 |
| 文本来源 | LLM 生成期产出，S0 已做逐 fact `store / skip` 准入 | 规则后处理复制 key_facts 文本 |
| 分类 | 生成期判定，无需事后分类 | 正则规则分类：实例 39% `unknown`，且存在“吃饭经过→planned”类错例 |
| 时间 | v3 `time` 契约：raw 必须出自源消息，程序按**源消息时间戳**换算（S2 已修） | `_parse_event_time` 以**写入时刻** `time.time()` 为基准，随写入延迟漂移 |
| 检索 | FTS + FAISS 双投影，词级分词（jieba），可重建、幂等、回滚 | 独立 FTS 单投影；无空格中文查询退化为短语/LIKE，句子级查询不可用 |
| 生产消费者 | S5 将按 fact hit 接入（`search_candidates` 已提供双路候选） | **无**：`search_memories()` 只用 hybrid/dual route，AtomRetriever 从不被调用 |
| 生命周期 | status 字段（active/building），S6 校准 | 独立 TTL/expire/forget/purge 定时任务，但过期不影响父文档召回，语义自相矛盾 |
| 存储成本 | 真源一份 + 可重建投影 | 每 fact 复制一份文本 + 复制整组 topics/participants 为 entities + 独立 FTS |
| 图谱 | S3 只消费 canonical facts 显式绑定 | `_extract_from_atoms` 独立建图路径（S4 已移除） |

禁止继续保持两套长期事实：一套真正被文档搜索使用，另一套只在后台过期。

## S4-02：对照实验

可复现脚本：`code/scripts/s4_atom_eval.py`（合成脱敏样本，纯离线，不需要 LLM/embedding），报告：`code/artifacts/s4_atom_eval_report.json`，verdict PASS。

| 检查项 | 结果 |
|---|---|
| 分类质量 | 5 个 atom 中 2 个错分类（40%）：两条**过去事件**（“上周六聚餐”“上周练车”）被规则分类为 `planned`——T0A 错例的可复现样本 |
| 时间基准 | 同一句“上周六”：canonical 按源消息（2026-08-15）归一化为 `2026-08-08`，atom 按写入时刻归一化为 `2026-08-22`，**差 14 天** |
| 检索命中 | 相关中文查询：canonical fact FTS 3/3 命中期望 fact；Atom FTS **0/3 全落空**（无空格中文句子查询退化） |
| 负注入 | 无关查询两边均不误命中 |
| 过期语义 | Atom 全部标记过期后：Atom FTS 0 命中，canonical fact FTS（连同父文档）仍命中——Atom 生命周期对生产召回无任何作用 |
| 复制成本 | facts 与 atoms 1:1 双份存储，Atom 另复制整组 topics/participants 与独立 FTS 索引 |

结论：Atom 无法向 S5 提供任何 canonical fact store 做不到的生产收益；方案 A 没有入选证据。

## S4-03B：停用独立 Atom（已实施）

- `MemoryEngine.initialize()` 不再初始化 AtomStore、AtomLifecycleManager、AtomRetriever；`atom_store` 恒为 `None`，所有旧的 `atom_store is not None` 守卫自动成为 no-op，无需逐个删除调用点。
- `atom_enabled` 配置键保留（兼容 schema），默认改 `False`，且即使显式 `True` 也不再驱动任何初始化。
- 新链路全部停止生成 Atom：
  - canonical 写路径（原本就 `atoms=None` + `skip_legacy_downstream`）不变；
  - `replace_memory`、`restore_memory`、Page API 导入入口不再调用 `classify_metadata_atoms`；
  - `MemoryProcessor.classify_atoms_from_metadata` 保留为纯函数（组件级测试引用），默认关闭，任何生产链路不再调用。
- `GraphExtractor._extract_from_atoms` 与 `extract()` 的 atoms 分支删除，`GraphMemoryManager` 的 atoms 参数链一并移除；图谱只从 canonical facts 建边。
- 不迁移、不清洗、不删除实例旧 Atom 数据；fork 新链路只停止生成和消费，测试只使用干净 fixture。
- 用户可见召回不受影响：生产检索从未经过 AtomRetriever，停用前后检索路径完全一致。

## S4-04：新链路处理

- 方案 B：新链路不再生成 Atom，也不启动任何相关后台任务；`memory_atoms` 表在干净 fixture 中不再被创建。
- 固定证据（tests）：`test_replace_memory_preserves_create_time_and_skips_atoms`（engine 初始化后 atom 三组件为 None、replace 不生成 atom）、`test_memory_archive_retains_document_and_restore_rebuilds_real_indexes`（archive/restore 全程 `memory_atoms` 表不存在）、`test_graph_extractor_ignores_atom_payloads`（extract 忽略 atom 载荷，v3 路径不受影响）。
