# S6：后置生命周期信号与必要体验

目标：S0-S5 的主链稳定后，再校准生命周期信号是否真实作用于召回，并补充必要的校对与表达体验。

本阶段不是承诺全部实施的 backlog。每项都必须说明真实消费者、用户收益和不实施的代价；纯展示最后做。跨记忆聚合和矛盾消解已移入 `Sfuture`，不属于本阶段。

## 任务索引

| ID | 类型 | 问题 | 任务 | 主要模块 | 状态 |
|---|---|---|---|---|---|
| S6-01 | FIX / FEAT | I08 | 为 S4 选定的事实真源设计生命周期 | lifecycle、fact store、retrieval | Deferred |
| S6-02 | OPT-S | I13 | 仅在确有收益时区分 retrieved / injected / adopted | search、event handler、decay | Deferred |
| S6-03 | UX | U01、U02 | 增加必要校对界面和表达设置 | WebUI、page API、formatting | Deferred |

## S6-01：真实生命周期

- 只作用于 S4 选定的唯一事实真源。
- importance、衰减和清理只解释“已经准入的 fact 后续保留多久”，不能替代或反向绕过 S0 的写入准入。
- TTL、reinforcement、forgetting 的状态变化必须直接改变生产召回。
- 不能再次出现子记录过期、父文档仍绕过状态提供同一事实。
- 生命周期规则必须能解释为什么保留、降权、归档或清除。

## S6-02：真实使用事件

- `retrieved` 表示进入候选，`injected` 表示送给模型，`adopted` 表示回答确实使用。
- 只有生命周期确实需要使用反馈时，才让 adopted 影响强化或衰减。
- 不再把“被搜索返回”直接当成“用户再次确认”。

## S6-03：界面与表达体验

- 只展示校对真正需要的来源、事实、路线、过滤原因和状态；不为实例旧数据建设迁移映射。
- 事实正文与可选 persona reaction 分开展示，不能重新合成大段第一人称日记。
- 支持查看为什么未召回，而不建设完整运维平台。
- 语气和格式选项不能反向改变 S5 的相关性和预算契约。

## 完成条件

- [ ] 每个启动项都有独立需求、真实消费者和验收样本。
- [ ] 未启动项保持 Deferred，不以空类、空表或后台任务伪装完成。
- [ ] 生命周期和体验改动不破坏 S0-S5 的写入、事实真源、图关系和注入预算。
