# S6：后置生命周期信号与必要体验

目标：S0-S5 的主链稳定后，再校准生命周期信号是否真实作用于召回，并补充必要的校对与表达体验。

本阶段只实施已有真实消费者的最小范围。跨记忆聚合、矛盾消解、rerank 和动态调权仍在 `Sfuture`，没有为它们预埋空状态或空流程。

## 任务索引

|---|---|---|---|---|---|

## 实现结果与边界

- importance、每日衰减、归档、恢复和删除已作用到唯一 canonical fact；父 document 只保留投影，不再能绕过 fact 状态进入生产召回。
- `retrieved` 只表示进入生产相关性结果，`injected` 只在事实真正放入自动或 Agent 请求后记录。只有 `injected` 会减缓后续衰减；调试页查询不会强化记忆。
- `adopted` 暂不实现：现有链路无法可靠判断模型是否真的使用了某条事实。与其把“已经注入”伪装成“回答采用”，本阶段保持无字段、无计数、无消费者。
- 归档会同时移除 fact FTS/向量投影；恢复从 authoritative fact 重建索引；批量删除先清事实层，避免留下可搜索孤儿。
- 召回页补充候选/最终数量、预算、路线与拒绝原因；记忆列表/详情改从 canonical store 读取权威 fact 对象，并把 fact 正文、topic、participant、来源消息、persona reaction、状态、被检索次数和实际注入次数分开展示，没有新增独立运维平台。
- v3 父记忆页不再允许把对象 fact 的正文、topic 或来源压回字符串；这里只能调整状态、类型和重要度。归档、恢复和软删除均走 canonical 生命周期并同步 FTS/向量索引；系统页用 fact 状态与索引一致性替代已停用的 Atom 统计。
- 注入提示只保留“相关历史作背景、当前消息优先、自然使用且不主动报菜名”的短契约；相关性和预算仍由 S5 在模型前保证。
- 事实涉及时间时直接在正文显示具体日期；详情不再展示独立事件时间对象。来源消息的发送时间仍可单独校对。

## S6-01：真实生命周期

- 只作用于 S4 选定的唯一事实真源。
- importance、衰减和清理只解释“已经准入的 fact 后续保留多久”，不能替代或反向绕过 S0 的写入准入。
- TTL、reinforcement、forgetting 的状态变化必须直接改变生产召回。
- 不能再次出现子记录过期、父文档仍绕过状态提供同一事实。
- 生命周期规则必须能解释为什么保留、降权、归档或清除。
- 承诺和约定与其他普通事实使用同一生命周期，不增加专用衰减豁免、到期状态或后台任务。

## S6-02：真实使用事件

- `retrieved` 表示进入候选，`injected` 表示送给模型，`adopted` 表示回答确实使用。
- 只有生命周期确实需要使用反馈时，才让 adopted 影响强化或衰减。
- 不再把“被搜索返回”直接当成“用户再次确认”。

## S6-03：界面与表达体验

- 只展示校对真正需要的来源、事实、路线、过滤原因和状态；不为实例旧数据建设迁移映射。
- 事实正文与可选 persona reaction 分开展示，不能重新合成大段第一人称日记。
- 支持查看为什么未召回，而不建设完整运维平台。
- 语气和格式选项不能反向改变 S5 的相关性和预算契约。
