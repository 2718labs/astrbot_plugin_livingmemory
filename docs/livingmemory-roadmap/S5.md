# S5：切换事实级召回与预算注入

目标：无关消息不注入长期记忆；相关消息只注入完成当前回答所需的最小事实。

S5 同时处理“候选是否相关”和“最终给模型看什么”，不再寄希望于提示词压住已经注入的垃圾。

## 已确认基线

- 每条允许范围内的非空消息都会进入 `search_memories()`。
- 当前 `top_k=4`，`recent_memory_count=2`；recent 绕过正常排名。
- 四条负向样本全部返回并注入 4 条记忆。
- 单次负向注入约 3310–3604 字符，还未计算本轮消息、人格和其他系统提示。
- 当前返回单位是十轮总结 document；格式化还会附加 Topics、Participants、全部 Key facts，并优先注入长篇 `persona_summary`。
- 实际运行中四条文档超过 3000 token 并不少见；`top_k` 只限制条数，无法控制每条长度。
- “陪伴插件在 GitHub 上叫什么”当前最终四条没有目标记录，说明候选池指标不能代替生产效果。

## 实现结果

- `MemoryEngine.search_memories()` 的生产入口已切到唯一 canonical fact 层；parent 只负责来源回链，命中一条 fact 不再展开同 parent 的其他 facts 或总结。
- 查询先形成较大的事实候选池，再按词面、向量和可选图信号拒绝证据不足的候选；笑声、寒暄、道别等明确轻量消息可在搜索前直接返回空，搜索后也允许零结果。
- recent 固定槽位已从生产链移除。时间只保留为同等相关候选之间的小幅排序信号，不能绕过相关性。
- document/graph 双路不再各自除以本路线最高分；弱路线低于绝对门槛时贡献为零。图权重默认保持 `0`，显式启用时也必须经过同一事实相关性门槛。
- 自动注入和 Agent 主动召回共用同一个 fact packer。默认总预算为 1200、单 fact 为 320，使用 UTF-8 字节数作为保守上界；只放完整事实，放不下就停止，不截断。
- persona reaction 只随命中的事实、在同一预算内作为独立短句附带；topic、评分、写入时间、parent summary 和 sibling facts 不进入默认载荷。
- 召回调试页区分候选 fact 数、最终注入 fact 数、预算、拒绝原因和路线原始信号；调试查询本身不记作真实使用。
- 固定评测脚本使用脱敏合成信号以保证结果可复现；真实 SQLite/FAISS、生产 `search_memories()` 与事件注入路径另由集成/烟雾测试覆盖。完整模型与连续体验 A/B 仍属于 `Stest`，本阶段不把固定样本成绩冒充最终体验结论。

## S5-01：最终生产验收

- 报告必须展示最终注入结果，不只展示 BM25、向量或图候选池。
- 使用真实配置顺序，分别记录候选 fact 数、最终注入 fact 数；标出每条为何进入、是否带 recent 信号、最终占用多少预算。
- 指标至少包含 Hit@最终 k、MRR、negative injection rate、空结果率、注入 token 和延迟。
- 评测版本与数据库快照绑定，避免把旧报告当成当前事实。

## S5-02：允许本轮不用记忆

- “触发了 LLM 请求”不再等于“必须注入长期记忆”。
- 明确记忆追问、稳定个人事实、关系延续和需要历史上下文的任务属于应召回候选。
- 寒暄、笑声、道别和无历史指向的新问题应能直接返回空。
- 需要时可以先搜索再判断，但证据不足必须 abstain，不能为了填满 `top_k` 返回低相关内容。
- 判断机制以可验证行为为准，不预设必须新增一次 LLM 分类调用。

## S5-03：可解释候选

- S4 无论选择 Atom 还是 canonical fact store，都必须向这里返回同一种 fact hit；S5 不再接受整篇 document 作为正常候选。
- 每个候选保留 fact ID、parent ID、BM25、vector、graph 原始信号、过滤原因和最终得分。
- 不用饱和后的融合分数假装成可比较的相似度门槛。
- document-only 只保留为改造前基准；图路线只有在 S3 证明有益后才进入生产比较。
- 路线调权必须在同一最终注入评测上显示稳定收益。

## S5-04：修复双路满信号归一化

- 当前问题不是“图权重设得高不高”，而是 document 与 graph 各自除以本路线最高分，使两边第一名都固定变成 1；这会把很弱的图第一名伪装成满信号。
- 融合必须保留或校准可跨路线比较的可信度，并允许任一路线在没有可靠结果时不贡献。
- 两条路线都很弱时，跨路线同时命中的奖励也不能把候选救成高可信结果。
- 路线图不预先写死某个公式；用 S3-06 固定样本比较可信度校准、带门槛的融合或排序融合，最终选择以生产注入结果为准。
- 固定回归：加入弱图候选后，强且正确的 fact/document 候选不得掉出最终结果；弱图路线不能只因非空就拿满图权重。
- 调试输出必须同时展示原始路线信号、校准后信号和最终得分；该回归未通过时图权重必须保持 0。

## S5-05：recent 参与排名

- recent 不再预留固定名额，也不绕过相关性判断。
- 时间只是一项候选信号；同等相关时可偏向较新事实。
- 已经由正常搜索命中的 recent 不重复占位。
- “最近发生但与当前问题无关”的记录必须被排除。

## S5-06：生产召回切换到 fact

- 查询先取得 fact 候选池，再做相关性拒绝、去重和排序；命中某个 parent 里的 fact B，不得自动带回 sibling facts A/C。
- parent memory 只用于来源回链和必要背景。只有单条 fact 脱离背景确实无法理解时，才允许附带一句有长度上限的中性 context。
- 同一 parent 命中多条相关 facts 时可以在展示上分组以节省重复来源信息，但仍按 fact 分别打分和计入预算。
- persona reaction 不独立搜索、不参与排序；只有对应 fact 被选中、反应非空且预算允许时才作为一小句可选载荷附上。
- document summary、全部 key facts、整组 topics/participants 和十轮对话不得作为 fact 命中的默认扩展载荷。

## S5-07：最小事实与硬预算

- 将候选池大小与最终注入量分开：可以取较多 fact 候选判断相关性，但不能把候选池直接塞给模型。
- 最终注入只使用 S1/S4 选定的完整 canonical fact，而不是整段 persona summary 或 parent document。
- 只携带回答所需的主体、事实、必要时间和条件。
- 默认去掉评分、写入时间、topic 列表、重复 facts 和长篇身份说明；只有消费者确实需要时才保留。
- 设置单 fact 上限和整轮 token 硬预算；按相关性装入完整 fact，下一条放不下时停止，不截成残句，也不固定塞满条数。
- 预算必须覆盖 reaction 和必要 context；不能只计算 fact 文本后再追加无限元数据。
- 具体默认 token 数由固定正负样本和目标模型 tokenizer 校准，不在路线图里凭感觉写死。
- 保留简短契约：历史仅供参考、当前消息优先、不宣布数据库；不继续堆叠重复否定指令。
- 旧实例 C2 的防复读 prompt 只提供一条可借鉴原则：相关记忆应作为背景自然使用，不为证明“记得”而主动报菜名。本阶段不照搬“昵称、旧承诺”等场景枚举，也不让模型用“不相关就忽略”替代前面的召回拒绝和预算机制。历史来源见旧调查文档 `memory-system-overhaul.md` 的 C2。

## S5-08：行为验收

- 正向：直接事实、间接追问、时效事实、同名歧义和跨记忆关联。
- 负向：笑声、吃什么、无关报错、晚安等当前已失败样本。
- 模糊：可能需要历史但证据不足，检查是否谨慎空结果或只给一条必要事实。
- 分开记录候选相关性、事实使用正确性、复述/宣布行为，避免把搜索错误算成表达错误。
- 同时固定“该自然使用”和“该保持沉默”的成对样本：用户明确追问旧事时可以直接回答，普通对话中不能主动宣布自己记得什么；防复读不能变成拒绝使用相关记忆。
- 对多事实 parent 建立固定样本：查询只命中其中一条时，最终注入不得出现同文档其他 facts 和整篇 summary。
- 对 persona reaction 建立有/无两类样本，验证它只随命中 fact、可为空、并计入同一预算。
