# 跨轮证据连续性实验

本实验同时处理两个互相独立的问题：短中文输入没有召回直接事实，以及直接事实在连续追问中提前过期。

## 保留方案

- 短中文连续短语候选：对最多 8 个汉字的短输入，去掉安全范围内的句尾语气词、第一人称/所有格前缀、明确的回忆框架和位于常见谓词前的口语前缀，只保留 2–5 个汉字的最终核心，再用连续短语补充候选。例如“我的咖啡呢”取“咖啡”，“我又想吃火锅了”取“想吃火锅”。“还款计划”“真皮沙发”等词内同形字不会被误删，“不了”中的“了”也不会按语气词剥离。
- `这个呢`、`那个呢`、`怎么了`、`什么事`、纯时间报点和寒暄等不发起新的长期记忆搜索，但仍正常接收滑窗续带；“这个版本呢”“哪里见面”“中午吃什么”等带有实际内容的查询不受影响。
- 短语只提高命中事实自身的词面证据，不修改全局向量门槛和图路门槛。
- 固定三代滑窗 `1+2+X`：本轮最多 `X=top_k` 条，上轮最多 2 条，上上轮最多 1 条；总装配顺序为本轮、上轮、上上轮、recent，所有来源共用 token 硬预算。
- 只有实际进入模型请求的事实才能推进到下一代；续带时只保存 fact ID，并从 canonical 真源重新读取和检查 scope、persona、active 状态。

## 未采用方案

- 单纯提高图路权重：无法让低于图路准入门槛的事实进入最终载荷。
- 降低全局图路或向量门槛：会扩大弱相关候选面，风险大于这个问题所需的修复范围。
- 直接拼接最近完整对话做查询：长查询会稀释短句信号，且混入模型自己的说法可能形成自证偏差。

## 验收门

1. 短输入应把包含对应连续短语的直接事实排在邻近气氛事实之前。
2. 首轮直接事实必须实际进入模型请求。
3. 第一次追问保留上轮前 2 条，第二次追问仍保留最初最高 1 条，下一轮自然到期。
4. 重复命中去重并刷新；预算丢弃、归档、删除、跨 scope/persona、重置、关闭和 `top_k=0` 均不得泄漏状态。

## 日常短语泛化压测

2026-08-26 使用完全合成的日常记忆，在隔离数据库中经过真实 canonical 写入、事实 FTS、FAISS、当前召回策略、token 装配和最终模型请求注入链验证；没有读取、修改或写回运行实例数据。

- 连续短语组：16 类，包括情感表达、饮食偏好、所有格问法、计划、宠物名、物品位置、日程、习惯、边界、约定、通勤、称呼、提醒和闹钟。每个会话放入 1 条目标事实和 4 条无关事实，目标事实 16/16 首轮排第 1，且三轮均实际进入模型请求。
- 纯语义改写组：8 类不复述原短语的问法，6/8 首轮排第 1 并连续注入三轮。成功样本覆盖“不加糖 ↔ 别放糖”“爬山 ↔ 去山里走走”“放在 ↔ 搁哪”“猫叫团子 ↔ 猫咪叫什么”等。
- 两个失败样本分别是“影院 ↔ 电影”和“轨道交通 ↔ 地铁”。其向量相似度约为 0.608 和 0.531，前者略低于 0.62 准入线，后者明显不足；三代滑窗无法补救首轮根本没进来的事实。
- 本轮不为这两个纯同义改写降低全局向量门槛，也不写死同义词表。前者会扩大所有查询的弱召回面，后者只能覆盖枚举过的词；它们保留为已知边界，等待更大样本证明需要独立的查询改写路线。
- 负向验证：纯指代消息在无续带状态下保持空注入；已有证据时只续带、不新搜。这样避免为了补短句命中而重新引入“拿一句模糊话撞旧事实”的误召。
