# 任务
从下面的私聊窗口中提取值得长期保存的事实。窗口只是来源范围，不等于一条记忆；按可独立复用的中心拆成零条、一条或多条记忆。

当前日期时间：{current_date}

# 消息格式
- `[M1]`、`[M2]` 是本窗口内的稳定引用编号，只能在 `source_indexes` 中使用这些编号。
- `[昵称 | ID: 账号 | 时间]` 是对方消息；`[Bot: 昵称 | ID: 账号 | 时间]` 是你的消息。
- 事实必须写具体昵称和完整主体，不能用“用户”“对方”“她”“他”“那个”“后来”等脱离来源就无法理解的指代。

# 对话历史
{conversation}

# 判断和拆分
- 每条候选事实独立选择 `store` 或 `skip`。
- `store`：窗口结束后仍可能复用的身份、偏好、关系、明确计划、重要事件、反复问题、重要决定，或明确要求记住的内容。
- `skip`：寒暄、一次性玩笑、临时报错过程、即时状态、重复无新增内容。
- 一条 memory 只围绕一个中心；彼此无关的事实放进不同 memory。
- 每条 fact 只表达一件事，并保留必要主体、时间、条件和状态。
- topic 是可跨记忆复用的概念，如“驾考”“睡眠”“插件开发”，不是一次性聊天标题。
- topics 和 participants 必须属于当前 fact，不得把整段窗口的标签复制给每条 fact。
- `source_indexes` 指向能够直接支撑当前 fact 的消息编号。
- `time` 只表示 fact 正文中明确提到的事件时间。`time.raw` 必须逐字摘自所引用消息的正文，不能复制消息头里的发送日期或时间；消息头时间只用于换算“昨晚”“周三”等相对时间表达。正文没有时间表达时必须写 null。
- `persona_reaction` 只记录你当时很短的情绪和想法；不复述 fact、不冒充人物事实，没有价值时写 null。
- summary 只写一句中性概览；程序会从获准 facts 重新派生它。

# 输出
只输出合法 JSON：

```json
{
  "memories": [
    {
      "summary": "张三周三要参加科目二考试",
      "topics": ["驾考"],
      "key_facts": [
        {
          "fact": "张三将在周三参加科目二考试",
          "action": "store",
          "topics": ["驾考"],
          "participants": ["张三"],
          "time": {"raw": "周三", "normalized": "2026-08-26", "precision": "day"},
          "importance": 0.8,
          "source": "user_explicit",
          "source_indexes": [1],
          "persona_reaction": {"emotion": "有些替她紧张", "thought": "希望她顺利通过"}
        }
      ],
      "sentiment": "neutral",
      "importance": 0.8
    }
  ]
}
```

约束：
- 顶层只能有 `memories`；最多 5 条 memory，每条最多 5 个 key_facts。
- `source` 只能是 `user_explicit`、`assistant_explicit`、`assistant_observed`、`group_consensus`、`inferred`。
- `time.precision` 只能是 `day`、`minute`、`month`、`year`。
- `sentiment` 只能是 `positive`、`neutral`、`negative`；importance 必须在 0.0 到 1.0。
- 不要为了让数组非空而编造事实；没有候选时输出 `{"memories":[]}`。
